[p]
CSG stands for <strong>Constructive Solid Geometry</strong>, and is a tool to combine basic
shapes or custom meshes to create more complex shapes. In 3D modeling software,
CSG is mostly known as &quot;Boolean Operators&quot;.
---
[p]
Level prototyping is one of the main uses of CSG in Godot. This technique allows
users to create the most common shapes by combining primitives.
Interior environments can be created by using inverted primitives.
---
[p]
The CSG nodes in Godot are mainly intended for prototyping. There is
no built-in support for UV mapping or editing 3D polygons (though
extruded 2D polygons can be used with the CSGPolygon3D node).
---
[p]
If you're looking for an easy to use level design tool for a project,
you may want to use <a class="reference external" href="https://github.com/func-godot/func_godot_plugin">FuncGodot</a>
or <a class="reference external" href="https://github.com/blackears/cyclopsLevelBuilder">Cyclops Level Builder</a>
instead.
---
[p]
You can check how to use CSG nodes to build various shapes (such as stairs or roads) using the
<a class="reference external" href="https://github.com/godotengine/godot-demo-projects/tree/master/3d/csg">Constructive Solid Geometry demo project</a>.

=== FILE: tutorials/3d/resolution_scaling.html (21 blocks) ===
[p]
Resolution scaling is one of the most direct ways to influence the GPU
requirements of a scene. In scenes that are bottlenecked by the GPU (rather than
by the CPU), decreasing the resolution scale can improve performance
significantly. Resolution scaling is particularly important on mobile GPUs where
performance and power budgets are limited.
---
[p]
While resolution scaling is an important tool to have, remember that resolution
scaling is not intended to be a replacement for decreasing graphics settings on
lower-end hardware. Consider exposing both resolution scale and graphics
settings in your in-game menus.
---
[p]
You can compare resolution scaling modes and factors in action using the
<a class="reference external" href="https://github.com/godotengine/godot-demo-projects/tree/master/3d/antialiasing">3D Antialiasing demo project</a>.
---
[p]
Resolution scaling is currently not available for 2D rendering, but it can be
simulated using the <code class="docutils literal notranslate"><span class="pre">viewport</span></code> stretch mode. See <a class="reference internal" href="../rendering/multiple_resolutions.html#doc-multiple-resolutions"><span class="std std-ref">Múltiples resoluciones</span></a>
for more information.
---
[p]
<strong>Bilinear:</strong> Standard bilinear filtering (default). This is used as a fallback
when the current renderer doesn't support FSR 1.0 or FSR 2.2. <em>Available in
all renderers.</em>
---
[p]
FSR1 upscaling works best when coupled with another form of antialiasing.
Temporal antialiasing (TAA) or multisample antialiasing (MSAA) should preferably
be used in this case, as FXAA does not add temporal information and introduces
more blurring to the image.
---

[p]
The rendering scale can be adjusted at runtime by changing the <code class="docutils literal notranslate"><span class="pre">scaling_3d_scale</span></code>
property on a <a class="reference internal" href="../../classes/class_viewport.html#class-viewport"><span class="std std-ref">Viewport</span></a> node.
---
[p]
Resolution scales <em>above</em> <code class="docutils literal notranslate"><span class="pre">1.0</span></code> can be used for supersample antialiasing
(SSAA). This will provide antialiasing at a <em>very</em> high performance cost, and is
<strong>not recommended</strong> for most use cases. See <a class="reference internal" href="3d_antialiasing.html#doc-3d-antialiasing"><span class="std std-ref">3D antialiasing</span></a> for more

---
[p]
The tables below list common screen resolutions, the resulting 3D rendering
resolution and the number of megapixels that need to be rendered each frame
depending on the rendering scale option. Rows are sorted from fastest to slowest
in each table.
---
[p]
The resolution scale is defined on a <strong>per-axis</strong> basis. For example, this
means that halving the resolution scale factor will reduce the number of
rendered megapixels per frame by a factor of 4, not 2. Therefore, very low
or very high resolution scale factors can have a greater performance impact
than expected.
---
[p]
When using the FSR1 or FSR2 scaling modes, the sharpness can be controlled using the
<strong>Rendering &gt; Scaling 3D &gt; FSR Sharpness</strong> advanced project setting.
---
[p]
The intensity is inverted compared to most other sharpness sliders: <em>lower</em>
values will result in a sharper final image, while <em>higher</em> values will <em>reduce</em>
the impact of the sharpening filter. <code class="docutils literal notranslate"><span class="pre">0.0</span></code> is the sharpest, while <code class="docutils literal notranslate"><span class="pre">2.0</span></code> is
the least sharp. The default value of <code class="docutils literal notranslate"><span class="pre">0.2</span></code> provides a balance between
preserving the original image's sharpness and avoiding additional aliasing due
to oversharpening.
---
[p]
Alternatively, you can set the scaling mode to <strong>FSR 2.2</strong> with the 3D
rendering scale set to <code class="docutils literal notranslate"><span class="pre">1.0</span></code> if you have enough GPU headroom. This also
provides high-quality temporal antialiasing. The <strong>FSR Sharpness</strong> setting
remains functional in this case.
---
[p]
The texture LOD bias currently affects both 2D and 3D rendering in the same way.
However, keep in mind it only has an effect on textures with mipmaps enabled.
Textures used in 2D don't have mipmaps enabled by default, which means only 3D
rendering is affected unless you enabled mipmaps on 2D textures in the Import
dock.
---
[p]
To counteract the blurriness added by some antialiasing methods, Godot also adds
a <code class="docutils literal notranslate"><span class="pre">-0.25</span></code> offset when FXAA is enabled, and a <code class="docutils literal notranslate"><span class="pre">-0.5</span></code> offset when TAA is
enabled. If both are enabled at the same time, a <code class="docutils literal notranslate"><span class="pre">-0.75</span></code> offset is used. This
mipmap bias offset is applied <em>before</em> the resolution scaling offset, so it does
not change depending on resolution scale.
---
[p]
Adjusting the mipmap LOD bias manually can be useful in certain scenarios,
but this should be done carefully to prevent the final image from looking
grainy in motion.
---
[p]
<em>Positive</em> mipmap LOD bias will make mipmapped textures appear blurrier than
intended. This may improve performance slightly, but is otherwise not
recommended as the loss in visual quality is usually not worth the
performance gain.
---

[p]
If performance doesn't increase much when decreasing resolution scale to a value
like <code class="docutils literal notranslate"><span class="pre">0.5</span></code>, it likely means the performance bottleneck is elsewhere in your
scene. For example, your scene could have too many draw calls, causing a CPU
bottleneck to occur. Likewise, you may have too many graphics effects enabled

possible to have certain parts of the viewport receive more detailed shading
than others. This is particularly useful in virtual reality (VR) to achieve

[p]
There are no size or aspect ratio requirements for the VRS density texture.
However, there is no benefit to using a VRS density map that is larger than the

[p]
Volumetric fog is only supported in the Forward+ renderer, not the Mobile or
Compatibility renderers.
---
[p]
Volumetric fog can be used at the same time as non-volumetric fog if desired.
---
[p]
Here is a comparison between traditional fog (which does not interact with lighting)
and volumetric fog, which is able to interact with lighting:
---
[p]
After enabling volumetric fog in the WorldEnvironment node's Environment
resource, you can edit the following properties:
---
[p]
<strong>Density:</strong> The base <em>exponential</em> density of the volumetric fog. Set this to
the lowest density you want to have globally. FogVolumes can be used to add to
or subtract from this density in specific areas. A value of <code class="docutils literal notranslate"><span class="pre">0.0</span></code> disables
global volumetric fog while allowing FogVolumes to display volumetric fog in
specific areas. Fog rendering is exponential as in real life.
---
[p]
<strong>Albedo:</strong> The Color of the volumetric fog when interacting with lights. Mist
and fog have an albedo close to white (<code class="docutils literal notranslate"><span class="pre">Color(1,</span> <span class="pre">1,</span> <span class="pre">1,</span> <span class="pre">1)</span></code>) while smoke
has a darker albedo.
---
[p]
<strong>Emission:</strong> The emitted light from the volumetric fog. Even with emission,
volumetric fog will not cast light onto other surfaces. Emission is useful to
establish an ambient color. As the volumetric fog effect uses
single-scattering only, fog tends to need a little bit of emission to soften
the harsh shadows.
---
[p]
<strong>Emission Energy:</strong> The brightness of the emitted light from the volumetric
fog.
---
[p]
<strong>GI Inject:</strong> Scales the strength of Global Illumination used in the
volumetric fog's albedo color. A value of <code class="docutils literal notranslate"><span class="pre">0.0</span></code> means that Global
Illumination will not impact the volumetric fog. This has a small performance
cost when set above <code class="docutils literal notranslate"><span class="pre">0.0</span></code>.
---
[p]
<strong>Length:</strong> The distance over which the volumetric fog is computed. Increase
to compute fog over a greater range, decrease to add more detail when a long
range is not needed. For best quality fog, keep this as low as possible.
---
[p]
<strong>Detail Spread:</strong> The distribution of size down the length of the froxel
buffer. A higher value compresses the froxels closer to the camera and places
more detail closer to the camera.
---
[p]
<strong>Ambient Inject:</strong> Scales the strength of ambient light used in the
volumetric fog. A value of <code class="docutils literal notranslate"><span class="pre">0.0</span></code> means that ambient light will not impact
the volumetric fog. This has a small performance cost when set above <code class="docutils literal notranslate"><span class="pre">0.0</span></code>.
---
[p]
Two additional properties are offered in the <strong>Temporal Reprojection</strong> section:
---
[p]
If you wish to hide distant areas from the player, it's recommended to
enable both non-volumetric fog and volumetric fog at the same time, and
adjust their density accordingly.
---
[p]
If fog light interaction is not desired for artistic reasons, this can be
globally disabled by setting <strong>Volumetric Fog &gt; Albedo</strong> to a pure black color
in the Environment resource. Fog light interaction can also be disabled for
specific lights by setting its <strong>Volumetric Fog Energy</strong> to <code class="docutils literal notranslate"><span class="pre">0</span></code>. Doing so will
also improve performance slightly by excluding the light from volumetric fog
computations.
---
[p]
While not physically accurate, it is possible to tune volumetric fog's settings
to work as volumetric <em>lighting</em> solution. This means that unlit parts of the
environment will not be darkened anymore by fog, but light will still be able to
make fog brighter in specific areas.
---
[p]
This can be done by setting volumetric fog density to the lowest permitted value
<em>greater than zero</em> (<code class="docutils literal notranslate"><span class="pre">0.0001</span></code>), then increasing the <strong>Volumetric Fog Energy</strong>
property on lights to much higher values than the default to compensate. Values
between <code class="docutils literal notranslate"><span class="pre">200.0</span></code> and <code class="docutils literal notranslate"><span class="pre">5000.0</span></code> usually work well for this.
---
[p]
There are a few project settings available to adjust volumetric fog performance
and quality:
---
[p]
Sometimes, you want fog to be constrained to specific areas. Conversely, you may
want to have global volumetric fog, but fog should be excluded from certain
areas. Both approaches can be followed using FogVolume nodes.
---
[p]
Make sure <strong>Volumetric Fog</strong> is enabled in the Environment properties. If
global volumetric fog is undesired, set its <strong>Density</strong> to <code class="docutils literal notranslate"><span class="pre">0.0</span></code>.
---
[p]
In the FogMaterial, set <strong>Density</strong> to a positive value to increase density
within the FogVolume, or a negative value to subtract the density from global
volumetric fog.
---
[p]
Configure the FogVolume's extents and shape as needed.
---
[p]
Thin fog volumes may appear to flicker when the camera moves or rotates.
This can be alleviated by increasing the
<strong>Rendering &gt; Environment &gt; Volumetric Fog &gt; Volume Depth</strong> project setting
(at a performance cost) or by decreasing <strong>Length</strong> in the Environment
volumetric fog properties (at no performance cost, but at the cost of lower
fog range). Alternatively, the FogVolume can be made thicker and use a lower
density in the <strong>Material</strong>.
---
[p]
<strong>Extents:</strong> The size of the FogVolume when <strong>Shape</strong> is <strong>Ellipsoid</strong>,
<strong>Cone</strong>, <strong>Cylinder</strong> or <strong>Box</strong>. If <strong>Shape</strong> is <strong>Cone</strong> or <strong>Cylinder</strong>,
the cone/cylinder will be adjusted to fit within the extents. Non-uniform
scaling of cone/cylinder shapes via the <strong>Extents</strong> property is not supported,
but you can scale the FogVolume node instead.
---
[p]
<strong>Shape:</strong> The shape of the FogVolume. This can be set to <strong>Ellipsoid</strong>,
<strong>Cone</strong>, <strong>Cylinder</strong>, <strong>Box</strong> or <strong>World</strong> (acts as global volumetric fog).
---
[p]
<strong>Material:</strong> The material used by the FogVolume. Can be either a
built-in FogMaterial or a custom ShaderMaterial (<a class="reference internal" href="../shaders/shader_reference/fog_shader.html#doc-fog-shader"><span class="std std-ref">Fog shaders</span></a>).
---
[p]
After choosing <strong>New FogMaterial</strong> in the <strong>Material</strong> property, you can adjust
the following properties in FogMaterial:
---
[p]
<strong>Density:</strong> The density of the FogVolume. Denser objects are more opaque, but
may suffer from under-sampling artifacts that look like stripes. Negative
values can be used to subtract fog from other FogVolumes or global volumetric
fog.
---
[p]
<strong>Emission:</strong> The Color of the light emitted by the FogVolume. Emitted light
will not cast light or shadows on other objects, but can be useful for
modulating the Color of the FogVolume independently from light sources.
---
[p]
<strong>Height Falloff:</strong> The rate by which the height-based fog decreases in
density as height increases in world space. A high falloff will result in a
sharp transition, while a low falloff will result in a smoother transition.
A value of <code class="docutils literal notranslate"><span class="pre">0.0</span></code> results in uniform-density fog. The height threshold is
determined by the height of the associated FogVolume.
---
[p]
<strong>Edge Fade:</strong> The hardness of the edges of the FogVolume. A higher value will
result in softer edges, while a lower value will result in harder edges.
---
[p]
<strong>Density Texture:</strong> The 3D texture that is used to scale the member density
of the FogVolume. This can be used to vary fog density within the FogVolume
with any kind of static pattern. For animated effects, consider using a custom
<a class="reference internal" href="../shaders/shader_reference/fog_shader.html#doc-fog-shader"><span class="std std-ref">fog shader</span></a>.
You can import any image as a 3D texture by
<a class="reference internal" href="../assets_pipeline/importing_images.html#doc-importing-images-changing-import-type"><span class="std std-ref">changing its import type in the Import dock</span></a>.
---
[p]
Since Godot 4.1, there is a NoiseTexture3D resource that can be used to
procedurally generate 3D noise. This is well-suited to FogMaterial density
textures, which can result in more detailed fog effects:
---
[p]
<span class="caption-text">Screenshot taken with <strong>Volume Size</strong> project setting set to 192 to make
high-frequency detail more visible in the fog.</span><a class="headerlink" href="#id1" title="Link to this image"></a>
---
[p]
To improve performance, it's recommended to use low texture sizes (64×64×64 or lower),
as high-frequency detail is difficult to notice in a FogVolume. If you wish to represent
more detailed density variations, you will need to increase
<strong>Rendering &gt; Environment &gt; Volumetric Fog &gt; Volume Size</strong> in the project settings,
which has a performance cost.
---
[p]
However, using a color ramp will <em>not</em> tint the fog volume according to the
texture. You would need to use a custom shader that reads a Texture3D to
achieve this.
---
[p]
In some cases, it may be better to use specially configured QuadMeshes as an
alternative to volumetric fog:
---
[p]
The fog effect has less realistic falloff, especially if the camera enters the fog.
---
[p]
Performance will not necessarily be better than volumetric fog if there are
lots of sprites close to the camera.
---
[p]
Set the <strong>Albedo &gt; Texture</strong> to the texture below (right-click and choose <strong>Save as…</strong>):
---
[p]
<em>After</em> setting the albedo texture, go to the Import dock, select the texture
and change its compression mode to <strong>Lossless</strong> to improve quality.
---
[p]
The fog's color is set using the <strong>Albedo &gt; Color</strong> property; its density is set
using the color's alpha channel. For best results, you will have to adjust
<strong>Proximity Fade &gt; Distance</strong> and <strong>Distance Fade &gt; Max Distance</strong> depending on
the size of your QuadMesh.
---
[p]
Optionally, billboarding may be left disabled if you place the quad in a way
where all of its corners are in solid geometry. This can be useful for fogging
large planes that the camera cannot enter, such as bottomless pits.
---
